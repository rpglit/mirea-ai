## 3. Детали по каждому багу

### BUG-1 (critical) — PNG-экспорт полностью неработает
- Файл: `frontend/js/exports.js:47` (`exportPng`), vendor-зависимость —
  `frontend/vendor/cytoscape.umd.js` (Cytoscape **3.30.2**).
- Механика: код вызывает `cy.png({ outputType: "png", scale: 2, bg: "#ffffff" }).then(resolve, reject)`.
  В Cytoscape 3.30.2 опция `outputType` неизвестна; режим возврата задаётся опцией `output`,
  и по умолчанию (`output` не задан) `cy.png()` возвращает **строку** data-URI
  (switch в `output()`: `case 'blob-promise' … default: return getB64Uri()`).
  Доказано зондом: `typeof window.Registry.net.png({scale:1})` → `"string"`,
  префикс `data:image/png;base64,iVBORw0K…`.
- Следствие: `.then` на строке → `TypeError: cy.png(...).then is not a function` →
  перехватывается try/catch обработчика кнопки (`frontend/js/app.js:379-386`) →
  пользователю показывается toast с **сырой JS-ошибкой** (см. `g-png-fail.png`),
  файл не скачивается. Касается обоих PNG: «PNG графа» для канваса сети и графа достижимости.
- FR-019 не выполнен. e2e-3 PNG не проверяет — поэтому штатный набор 5/5.
- Направление фикса (не применялось): `cy.png({ output: "blob-promise", scale: 2, bg: "#ffffff" })`.

### BUG-2 (major) — подписи весов дуг не отображаются ни на одной дуге
- Файл: `frontend/js/net-canvas.js:140-144` — правило
  `{ selector: "edge[data(weight) = 1]", style: { label: "" } }`.
- Селектор невалиден в Cytoscape 3.30.2: синтаксис data-сравнения — `edge[weight = 1]`
  (ключ без `data()`). Проверено изолированно: `[base, невалидное правило]` →
  у **всех** дуг label = `""` (в т.ч. у дуг с весом 2 и 3); `[base]` → label `"2"`, `"1"`;
  `[base, 'edge[weight = 1]']` → `"2"` / `""` без предупреждений.
  Т.е. невалидное правило, стоящее последним, глушит label всех дуг (побочный эффект
  cytoscape), а не просто игнорируется.
- Факт на эталонной сети: 5/5 дуг с весом > 1 без подписи (`a-net-initial.png`),
  0/10 дуг с весом 1 показывают «1». Console-warning при каждом создании канваса сети.
- FR-015.1 п.1 «arcs with weight > 1 display the weight» не выполнен.
- Направление фикса (не применялось): `edge[weight = 1]`.

## 5. Console-ошибки по сценариям (аудит «никаких console-ошибок при типовых сценариях»)

Снимались `page.on('console')` (type=error/warning) и `page.on('pageerror')` на каждом
сценарии. JS-ошибок (pageerror) — **0 во всех сценариях**.

Выводы аудита:
1. **Жёстких JS-ошибок в console нет** ни в одном сценарии — обработка ошибок
   клиентская (toast). Сетевые записи `422` в сценариях i2/i3/i5 — штатный лог браузера
   на 4xx-ответы API, не дефект JS.
2. **Нарушение «чистого» console есть**: warning `edge[data(weight) = 1] is invalid`
   (BUG-2) появляется при каждой загрузке любой сети — это и есть console-шум при
   типовых сценариях a–h. Плюс 2 предупреждения Cytoscape о `wheelSensitivity: 0.2`
   (косметика, не влияет на поведение).
3. При ошибке PNG в toast выводится сырое сообщение JS-типа (BUG-1) — для пользователя
   это выглядит как «внутренняя ошибка», хотя в console-аудите ошибки нет.
