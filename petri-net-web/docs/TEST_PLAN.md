## 1. Цели и область

### В области (раунд 2)

- **Доменные модули** (без изменений раунда 1 + v2): семантика сети
  (S = (P, T, I, O, µ0), разрешённость, срабатывание, A-06), три канала ввода
  (текст/JSON/форма) + v2-поля (inhibitors/priorities/delays/colors),
  граф достижимости + дерево Кэрпа–Миллера (включая ингибиторы), свойства
  (boundedness/safety/k, liveness L0–L4, тупики, мёртвые переходы, home state,
  conservative, вердикт «живая/тупиковая/частичнотупиковая», µmin).
- **Решатели (новые)**: единый `solve(task_id, data)`, каталог 71 задачи
  (PN 40 / LSS 23 / FA 8) + custom-маршрутизация; отчёты «Дано/Найти/Решение/
  Ответ/Пояснения»; М1–М11 для ЛСС (sympy), моделирование автоматов по тактам.
- **API**: все маршруты раунда 1 + новые: `POST /solve` (без состояния,
  таймаут 30 с, LRU-кэш), `GET /catalog` (+prefill), `POST /matrices`,
  `POST /minimal-marking`, `POST /properties` (+with: matrices/mu_min/sequence),
  `GET /sessions?limit=`, `POST /parse` (v2-поля, имя); русские
  `error.message` (коды английские), коды 409/413/422/404/500
  (`unknown_task`, `conflict`, `cap_exceeded`, `unsupported_model`,
  `solver_failed`).
- **UI (Vue 3 + Vite + Cytoscape)**: экран «Сеть Петри» (ввод, канвас сети с
  зелёными разрешёнными переходами, граф достижимости с подсветкой текущего
  узла, пошаговое проигрывание one-click, свойства по глоссарию, проверка
  маркировки, экспорт PNG/JSON/CSV, именованные сессии) и экран «Задание из
  практикума» (каталог 71, предзаполнение, решение, отчёт, графы автоматов с
  проходом слова по тактам, PNG всех канвасов).
- **E2E (Playwright)**: сценарии E2E-1…E2E-8 + проверка «console чистый»
  (NFR-107: 0 ошибок и 0 warning во всех сценариях).

### Вне области

- CI-пайплайны (гейты запускаются вручную в контейнерах).
- Нагрузочное тестирование (NFR-101 — бюджет одиночного запуска).
- Безопасность (аутентификации нет, секретов нет).
- Хост-окружение: всё в Docker (NFR-106).

## 5. E2E-сценарии (Playwright, `e2e/test_e2e.py`)

Общие: `http://app:8000`; UI — русский; ожидание — поллинг по DOM (без fixed
sleep). **Каждый сценарий** дополнительно падает, если в console браузера
появилась хоть одна ошибка или warning (NFR-107, конвейер `page.on("console")`
в `conftest.py`).

- **E2E-1** — текстовый ввод + полный анализ: «узлов: 1503, рёбер: 4983»,
  11 узлов сети, свойства (k=29, L1, 23, «нет» мёртвых); скриншот
  `docs/acceptance/e2e-1-analysis.png`.
- **E2E-2** — проигрывание: 5 активных; one-click по t1 → «p1 (5)»/«p2 (5)»;
  «Отмена» → «p1 (7)»; «Срабатывание» → «p1 (5)»; клик по первому шагу
  истории → «p1 (5)»; «Сброс» → история пуста, «p1 (7)».
- **E2E-3** — экспорт: CSV (заголовок `p1,p2,p3,p4,p5,p6`, 1504 строки,
  2-я строка `7,4,2,5,4,3`, без ω) и JSON (k=29, L1, 23 тупика).
- **E2E-4** — JSON-ввод: те же 1503/29/L1/23.
- **E2E-5** — история сессий: список ≥1, клик → восстановление без
  пересчёта (1503 узла, k=29).
- **E2E-6** — «Задание из практикума»: 71 карточка; фильтр «Сети Петри» → 40;
  карточка PN-05 → prefill (initial_marking в JSON); «Решить» → отчёт
  Дано/Найти/Решение/Ответ с итоговой маркировкой (5,3,4,6,3,3); скриншот
  `e2e-6-solve-pn.png`.
- **E2E-7** — FA-03: граф автомата 4 вершины; прохождение слова p1 p2 p2 p1 p2
  (s0 s0 s1 s3 s3 s0): «Показать прохождение» → 1 текущее состояние;
  «Следующий такт»; «Показать весь путь» → 3 посещённых вершины; скриншот
  `e2e-7-fa-graph.png`.
- **E2E-8** — PNG: сеть, граф и «PNG всех» — валидные PNG-файлы
  (магика `\x89PNG`, размер > 1 КБ).

При падении — скриншот в `docs/acceptance/failures/`.

## 6. Входы/выходы

Вход: сборка обоих образов; app healthy (`/healthz` → 200).

Выход: юнит+property, ruff, mypy strict и e2e — зелёные; счётчики/длительности —
в TEST_REPORT; любой красный — воспроизведён канонической командой с
описанием; артефакты на месте.

## 7. Риски

| Риск | Влияние | Митигция |
| ---- | ------- | -------- |
| 1503 узлов в headless Chromium — медленно | flaky-ождания | поллинг по реальному DOM-состоянию с большими таймаутами |
| Дрейф версии Playwright | несовместимость e2e-контейнера | пин `v1.49.1-jammy` |
| npm-зависимости на этапе сборки | сбой сборки | образы на пинах в `package.json`; сборка только в Docker |
| sympy-нестабильность формул | «красивость» LSS-ответов | канонизация `sp.simplify`/`cancel`; эталоны зафиксированы строками |
| Console-чек слишком строгий | ложные падения e2e | предупреждения Cytoscape устранены в корне (D-055); чек — требование NFR-107 |
| SQLite накапливает сессии между прогонками | влияние на список сессий | ассерты с допуском (≥1, новые первыми) |
