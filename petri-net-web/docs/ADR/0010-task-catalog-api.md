# ADR-0010: Каталог задач TASK-XX как данные + API решателей

Status: Принята (08.10.2026, раунд 2)

## Контекст

Фаза 1 (D-044/D-045) зафиксировала каталог **71 задания** архива методички —
PN 40, LSS 23, FA 8 — в `MATERIALS_ANALYSIS.md` §3 (карточки: ID, источник,
условие-цитата, метод, эталон). Цель раунда 2 (D-041): пользователь выбирает
задание в UI («Задание из практикума»), вводит/подставляет данные, получает
отчёт методички; e2e-приёмка проверяет каждый эталон. Если бы логика
«какое задание, как решается, что дано» жила в коде фронтенда и API
разрозненно — каталог было невозможно было бы поддерживать (71 карточка,
правки методички) и тестировать. API раунда 1 ломать разрешено (D-041:
единый `main`, внешних потребителей нет).

## Решение

- Каталог — **данные**: реестр `CATALOG: dict[task_id → TaskInfo]` в
  `solvers/__init__.py`, `TaskInfo = {task_id, group, title, source, type,
  input_kind, fn}` — транскрипция карточек `MATERIALS_ANALYSIS.md` §3
  (условие-цитата и метод — в `title`/`source`/карточке; `fn` — функция
  решателя из ADR-0008). Новое задание = одна запись + тест эталона.
- Новые эндпоинты (подробности — §2.6 ARCHITECTURE):
  - `GET /catalog` → список `{task_id, group, title, source, type, input_kind}`
    (фильтр `?group=PN|LSS|FA`);
  - `POST /solve {task_id, data}` → `Report` — **без состояния**: не требует
    и не создаёт сессию;
  - `POST /matrices {session_id}` → W−/W+/W (М7);
  - `POST /minimal-marking {session_id, parallel?}` → µmin (М6);
  - `POST /properties` — расширение: `conservative`, `verdict`
    (живая/тупиковая/частичнотупиковая), `mu_min`, `sequence`
    (шаги + v(σ) + µ′).
- Пользовательские (не из методички) задания той же структуры решаются
  как `task_id: "custom:<группа>"` — тот же `Report`, те же валидации.
- Все `error.message` — на русском (коды — английские, ADR-0006); новые
  коды: `unknown_task` (422), `conflict` (409), `unsupported_model` (422),
  `solver_failed` (500).
- Имена сессий: `name` (уже в storage) обязателен в UI при создании;
  `GET /sessions` — `limit` (по умолчанию 50, новые первыми) — закрывает
  BUG-8/BUG-9.

## Последствия

- UI «Задание из практикума» тривиален: `GET /catalog` → карточка →
  форма ввода по `input_kind` (§4 ARCHITECTURE) → `POST /solve` →
  рендер `Report` (ReportPanel/AutomatonCanvas/LssReport).
- Приёмка формализуется: эталоны §8 `MATERIALS_ANALYSIS` — ожидаемые
  `answer`-поля отчётов (LSS-08/09/10/11/12/13/17…23, FA-01…06 — из
  методички; LSS-01…05/14/15, PN-02…09/19/21 — эталоны Фазы 5,
  вычисляются независимо и сверяются двумя независимыми реализациями).
- `POST /solve` без состояния: повторяемое решение — повторный запрос;
  SQLite не растёт от решателей. Цена: отчёт не виден в истории сессий,
  если UI не сохранил его в именованную сессию (для PN — сеть парсится в
  сессию автоматически).
- API раунда 1 меняется (новые коды ошибок, русские сообщения, `limit`) —
  e2e-набор раунда 1 переписывается под контракт раунда 2 (D-041).
- Каталог не дублирует условия в `GET /catalog` (только метаданные +
  ссылка на карточку): полные цитаты условий остаются в
  `MATERIALS_ANALYSIS.md` — единственный источник.
