# ADR-0009: Расширенная модель сети (inhibitor / приоритеты / τ / цвета / параллельные fire)

Status: Принята (08.10.2026, раунд 2)

## Контекст

Модель раунда 1 — классическая S=(P,T,I,O,µ) (ADR-0001). Методичка оперирует
более широким классом сетей (семинары 2–5, 7): **ингибиторные дуги**
(⊣: переход разрешён, только если в позиции 0 меток — PN-33, TASK-PN-33),
**приоритеты** Pr t (конфликт решается в пользу большего — PN-10, 30),
**временные сети** (τ на выходных дугах, метка доступна с t+τ, по умолчанию
τ=1 — PN-15, 32), **цветные сети** (метки = объекты со значениями, гварды на
входных дугах, выражения на выходных — PN-36/37, scope A-21), **параллельное
срабатывание** бесконфликтного подмножества (принцип максимального
параллелизма — PN-07: «параллельные t1 и t2»). GAP: 5 из 40 PN-задач
«не решаются» именно из-за отсутствия этих конструкций.

## Решение

- `PetriNet` расширяется до **v2** (frozen dataclass, ADR-0001 сохраняется):
  новые поля `inhibitors` (⊣(t): [p], вес 1), `priorities` (Pr t, None —
  нет), `delays` (τ на **выходных** дугах, как в методичке), `colors`
  (опциональный слой `Colors`: initial_values / guards / output_exprs —
  только данные). JSON-схема расширяется теми же опциональными полями
  (ADR-0003, pass 2 — кросс-полевые проверки).
- Разрешённость: `enabled(net, m, t, *, usable=None)` — `m[p] ≥ w` для всех
  входных дуг **и** `usable[p] == 0` для всех ингибиторов; `usable` —
  вектор «доступных сейчас» меток (по умолчанию `m`): τ-доступность
  вычисляется вне core.
- Срабатывание: `fire` — без изменений (одиночное); **`fire_set`** —
  параллельный шаг: все переходы разрешены и попарно не конфликтуют
  (общая входная позиция — конфликт по глоссарию методички), иначе
  `ConflictError` (409). `active()` при `priorities` оставляет в каждой
  конфликтной группе максимум Pr t.
- Новые функции core: `incidence()` (W−/W+/W, метод М7),
  `minimal_marking(parallel=...)` (М6; параллельный случай — сумма
  требований конфликтующих).
- Время: **core время не ведёт** — дискретная симуляция по тактам живёт в
  `solvers_pn` (метка, помещённая в p в такт n, доступна с n + τ(p)).
  Полные графы достижимости для сетей с `delays` или `colors` не
  строятся: `build` → `UnsupportedModelError` (422) — пространство
  «маркировка × время/значения» не конечно. Анализ таких сетей — только
  симуляция с горизонтом.
- Цветной слой: core хранит данные, семантику (оценка гвардов, выражения)
  реализует `solvers_pn` на безопасном парсере арифметических выражений
  (произвольный код не выполняется); scope A-21 — пошаговые примеры,
  без классификации и достижимости.

## Последствия

- Совместимость: при всех новых полях `None`/пустых поведение **идентично**
  раунду 1 — якоря D-009…D-014, D-035 (1503/4983, k=29, L1, 23 тупика)
  не меняются; текстовый канал парсера не тронут.
- Новые ошибки: `ConflictError` (409), `UnsupportedModelError` (422) —
  добавляются в таблицу ADR-0006.
- Кэрп–Миллер с ингибиторами: правило «ω-метка блокирует ингибиторную дугу
  навсегда» (ω ≥ 1, ингибитор требует ровно 0); для временных/цветных —
  режим недоступен (422), что отражено в UI (предложение симуляции).
- Точность выводов для временных/цветных сетей ограничена горизонтом
  симуляции (`SOLVER_MAX_STEPS = 1000`) — отчёт помечает это в `notes`.
- Приоритеты не меняют множества достижимых маркировок (последовательные
  срабатывания) — графы раунда 1 для сетей с Pr остаются корректными.
