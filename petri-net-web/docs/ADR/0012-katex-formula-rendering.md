# ADR-0012: LaTeX-рендеринг формул — KaTeX 0.19.0 локально (npm/Vite) + аддитивные *_tex

Status: Принята (09.10.2026, раунд 3)

## Контекст

FR-502 — отчёт LSS с формулами (y(t), g(t,τ), Φ(s), A(ω)/φ(ω), (sE−F)⁻¹, W(s));
итерация 3 (D-058; REQUIREMENTS §7–8: FR-603, FR-604, FR-605, NFR-110, NFR-112).
Раунд 2: формулы рендерятся HTML+`<sub>/<sup>` по `Step.text`, `Step.latex`
зарезервировано, KaTeX в базовой сборке **не** входит (ADR-0007). Решение
пользователя (D-058): «как лучше, но всё локально» — **без CDN**. Аудит
`MATH_RENDER_PLAN.md` (фаза 1.3) зафиксировал полную карту 35 «мест с
математикой»: 14 → рендерятся формулами, 21 → plain (включая ВСЕ e2e-якоря);
совместимость sympy→KaTeX проверена заранее (63 уникальные LSS-строки,
126/126 рендеров `renderToString` без ParseError, 0 console-проблем).

## Решение

- **Библиотека: KaTeX 0.19.0** (актуальная версия, 09.10), **только npm**,
  точный пин без `^`, бандлится Vite (build stage, ADR-0007). Оффлайн-
  гарантия: после сборки приложение не обращается в сеть ни за JS, ни за
  шрифтами (в отличие от CDN-подхода). MathJax отклонён: тяжелее
  (~1 МБ JS против ~273 КБ), асинхронный рендер ломает e2e-тайминги,
  детерминированного `renderToString` нет.
- **Рендер — явный `katex.renderToString(tex, {displayMode, throwOnError:true})`
  на каждую формулу; auto-scan (auto-render) НЕ используется**: детерминированный
  DOM для e2e, контроль перфоманса, нет глобального сканирования текста.
  `katex.min.css` — импорт в `main.js`; в бандле ВСЕ 20 woff2 (сабсет отклонён:
  ломает обновления KaTeX, экономит только «на диске», не в загрузке).
  `contrib/copy-tex` не используется (свой UX ниже). KaTeX импортируется
  ровно в двух местах: `main.js` (css) и `Formula.vue` (JS).
- **Размер бандла**: статика 572 КБ → **~1,16–1,18 МБ** (+~590–610 КБ на диске:
  JS ~273 КБ min + CSS 24,8 КБ + 20×woff2 296 КБ); фактическая загрузка первого
  экрана +~330–370 КБ (браузер lazy-тянет только 4–6 реально используемых
  woff2 ≈ 50–70 КБ по глифам). gzip в стеке нет (FastAPI-статика) — цифры
  «как есть». Оценка приемлемая для локального учебного приложения
  (оффлайн приоритетнее размера) — риск 11 ARCH §6 + мониторинг в e2e.
- **`Formula.vue`** (контракт): props `tex` (обязателен), `display`, `label`.
  DOM: корень всегда `<span class="formula [formula--display]" role="math"
  aria-label="{tex}" title="{tex}" data-tex="{tex}">` (класс `formula` на
  корне — замороженный e2e-селектор) + `.formula__katex`
  (`aria-hidden="true"`; проверено: innerText не скрывается) + клавиатурно
  достижимая кнопка `.formula__copy` (hover/focus-within). При ParseError —
  **fallback = escaped исходник** (`<code class="formula__fallback">`) в том же
  стиле токенов: исключение не пробивается в приложение, в console ничего не
  пишется (NFR-107). Копирование: `navigator.clipboard.writeText(props.tex)`
  → тост «TeX скопирован»; отказ → `execCommand("copy")`; оба отказа →
  error-тост. `aria-label`/`title` = TeX-исходник (KaTeX-опция `ariaLabel`
  атрибут НЕ ставит — проверено; MathML-часть KaTeX с `<annotation>`
  дополнительно доступна скринридерам и даёт текст для innerText).
- **Аддитивные `*_tex` поля в отчётах решателей** (принцип ADR-0008: поля
  отчёта — только аддитивные): рядом со старыми ключами — только НОВЫЕ; старые
  `str()`-значения не трогаются → существующие строковые ассерты бэкенда и
  JSON-регрессия всех 71 задачи остаются зелёными. 15 имён в `answer` и
  `solution[].data` (по kind — MATH_RENDER_PLAN §4.3): `P_tex, y_h_tex,
  y_p_tex, y_tex, roots_tex, g_tex, phi_tex, A_tex, phi_f_tex, F_iw_tex,
  law_tex, W_tex, x0_equations_tex, x0_tex` + `given.statement_tex`
  (23 LSS-задачи, hand-written TeX) и `law_tex` 11 стандартных звеньев
  (hand-written). **LSS — генерация `sp.latex(expr)` на бэкенде**: детерминизм
  проверен (двойной прогон — JSON идентичен; 63 строки стабильны); пере-
  `sympify(str)` клиентом не используется (неоднозначно: дроби, `I`, `pi`).
  Поле `Step.latex` (раунд 2) в отчётах не заполняется — заменено `*_tex`.
- **Клиентский генератор TeX для PN/FA**: `frontend/src/math/tex.js` — чистые
  функции без зависимостей от Vue (юнит-тестируемы): `tupleToTex`,
  `markingToTex`/`omegaTupleToTex` (null→`\omega`), `matrixToTex`,
  `ioMatrixToTex` (array + `\hline`, лейблы p/t), `sigmaToTex`, `labelTex`
  (`p1`→`p_1`), `faEnumToTex` (φ/ψ; несовпадение → null — caller оставляет
  plain), `fracTex` (символьные ячейки F). **Правило разграничения**:
  идентификаторы (состояния `s0`, переходы `t1`, выходы `w0`, позиции `p1`)
  в списках и прозе — plain; Formula получают только формульные значения
  (выражения, маркировки/кортежи чисел, матрицы, уравнения, φ/ψ-перечисления).
- **Сохранение e2e-якорей** (MATH_RENDER_PLAN §7.3 — 0 переписываний
  существующих ассертов; что остаётся **plain**): `#props` — «L1», «23»,
  «нет» (plain); «k = 29» → Formula, якорь «29» жив через MathML-часть KaTeX
  (ассерт не меняется); FA-отчёты — `w0`, `s3` (идентификаторы); StepPanel —
  history-line `(7,4,2,5,4,3) → … (t1)`, кнопки `t1` (`#active-list`
  заморожен); NetCanvas — `p1 (5)` (SVG-лейблы, `wait_net_label` заморожен),
  ⊣/τ-подписи; graph-stats «узлов: 1503» (`wait_analysis`); входной текст
  `#input-text` (парсер); карточки TaskPicker (71 × KaTeX — перфоманс);
  ANSWER_LABELS-подписи и notes-проза. PN-05 `(5,3,4,6,3,3)` → Formula,
  ассерт E2E-6 не меняется (HTML-часть TeX без пробелов сплошная — проверено;
  tex генерируется без пробелов). Замороженные селекторы: `.formula` (теперь
  корень Formula.vue), `#props`, `.report`, `.step-text`, `.task-card`,
  `window.Registry.*`. `step.text` — `<pre class="step-text">` сохраняется,
  встроенные сырые формулы заменяются инлайн-Formula по raw→tex карте из
  `answer`/`solution[].data` (детерминизм: бэкенд собирает текст из тех же
  str-значений).
- **Приёмка**: e2e-сценарий **E2E-10** (MATH_RENDER_PLAN §6.3): LSS-14 —
  `.report .katex` присутствует, ≥6 формул, `aria-label` содержит TeX
  (проверка через `page.evaluate`, не CSS-атрибутным селектором), копирование
  TeX (новый clipboard-fixture) + тост; PN-05 — якорь `(5,3,4,6,3,3)`
  сохранён + `.report .katex` ≥3; console чистый (NFR-107). Скриншоты
  `docs/acceptance/math/` (LSS-14 report, PN-05 report, PropertiesPanel
  k=29/тупики/µmin). Бэкенд-тесты `test_solvers_lss_tex.py` (presence по
  kind + детерминизм `sp.latex` + жёсткие эталонные строки); юнит —
  `tex.js` (~15 кейсов) + `Formula.vue` (jsdom, включая fallback на кривой
  TeX).

## Последствия

- **Заменяет пункт ADR-0007** «KaTeX не входит в базовую сборку»: KaTeX 0.19.0
  — часть сборки (локально, без CDN); поле `Step.latex` остаётся в контракте,
  решатели его не заполняют.
- Контракт отчёта растёт аддитивно (`answer`/`solution[].data`/`given` +
  `*_tex`): детерминированный порядок ключей сохраняется, `_jsonify` строки
  пропускает прозрачно; старые e2e и бэкенд-тесты без изменений.
- Статика ~1,16–1,18 МБ (риск 11 ARCH §6): все 20 woff2 в бандле, браузер
  lazy-грузит подмножество; мониторинг e2e — 0 network-404, ровно 20
  `assets/*.woff2`, сверка `du -sk static` после сборки.
- Токены `--pn-formula-*` (ADR-0011) — единый визуальный язык формул во всех
  темах; `Formula.vue` без hardcoded-цветов.
- Остаточные prose-фрагменты вне raw→tex карты (`e^{st}`, `s^i` в step.text) —
  plain, принято (MATH_RENDER_PLAN §5.1/Q5); символ `y0p` (LSS-22) — как
  выводит `sp.latex` (косметика, принято).
- **Бюджет производительности ит. 3 зафиксирован (NFR-112)**: полный
  browser-сценарий (открытие → анализ → граф + свойства готовы) ≤ 5 с:
  статика кэшируется (immutable, FR-612), рендер графа 1503 узлов — не хуже
  якоря аудита ~2.8 с (FR-609 снижает), темы не вызывают re-layout (ADR-0011);
  `/solve` не блокирует event loop (ARCH §2.6).
