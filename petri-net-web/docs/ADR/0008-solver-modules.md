# ADR-0008: Пакет решателей solvers (PN/LSS/FA), единый Report

Status: Принята (08.10.2026, раунд 2)

## Контекст

GAP-анализ: PN — 21 из 40 заданий решается, 14 частично; **LSS — 0 из 23,
FA — 0 из 8** (модулей нет). Цель раунда 2 (D-041): уверенно решать все 71
задание каталога (`MATERIALS_ANALYSIS.md` §3) и любые аналогичные, в формате
методички «Дано / Найти / Решение (шаги) / Ответ» + пояснение своими словами.
LSS — символьная математика (ОДУ с НУ, δ-вход, передаточная подстановкой
e^{st}, АЧХ/ФЧХ, пространство состояний, СЛАУ для X(0)): ручной набор
алгоритмов хрупок, а **sympy** даёт точную (рациональную) арифметику,
`Matrix.inv` для (sE−F)⁻¹ и факторизацию характеристического многочлена.
FA — конечная дискретная модель: автомат A = <P, S, s0, φ[, W, ψ]> трёх типов
(без выхода / Мура / Мили), три способа задания, детерминированное
моделирование слова по тактам, конструкция Мура→Мили — всё считается
точно, символьный движок не нужен.

## Решение

- Новый фреймворк-свободный пакет `backend/src/petrinet/solvers/`:
  `__init__.py` (реестр, `solve`, `catalog`), `report.py`, `solvers_pn.py`,
  `solvers_lss.py` (+ `links.py` — таблица 11 стандартных звеньев),
  `solvers_fa.py` (+ `automata.py` — модель автомата).
- Единый контракт отчёта для всех трёх областей:
  `Report = {task_id, given, find, solution: [Step], answer, notes}`,
  `Step = {step, title, text, latex?, data?}`; сериализация — JSON с
  sorted ключами. `text` — человекочитаемый шаг (формулы unicode),
  `data` — машиночитаемые артефакты (таблицы, векторы, матрицы),
  `latex` — зарезервировано для опционального KaTeX (ADR-0007).
- Точка входа: `solve(task_id, data) -> Report`. LSS: точная арифметика
  sympy, порядок ОДУ ≤ 6, таймаут 30 с → `SolverError` (500 `solver_failed`);
  повторные вызовы с тем же `spec` — кэш на процесс. FA: полный автомат
  (все пары P×S в φ — иначе 422), Мура — w0* в t0 не учитывается, Мили —
  t0 без выхода (конвенции методички, §7.3 М4).
- Решатели PN не дублируют ядро: построение/разрешённость/срабатывания —
  `core`, граф и свойства — `reachability` + `properties` (включая новые
  вердикты, консервативность, W±, v(σ), µ′), временные/ингибиторные/
  цветные сценарии — симуляции поверх `core` с `usable`.

## Последствия

- Зависимость `sympy` (runtime, `pyproject.toml`): растёт образ и время
  сборки; точные вычисления могут быть медленными — ограничено капами
  (порядок, таймаут) и кэшем; 11 стандартных звеньев — из таблицы, не
  пересчитываются.
- Появляется новый класс ошибок 500 `solver_failed` (в раунде 1 — только
  4xx + 500 `internal_error`): решатель упал на «нестандартном» вводе —
  пользователь получает русское сообщение, а не стектрейс.
- Отчёты решателей **без состояния** (не хранятся в SQLite): история
  сессий хранит только PN-сети/графы/отчёты свойств; сохранение отчёта
  решателя в историю — через именованную сессию (UI).
- Добавление нового задания каталога = запись `TaskInfo` + тест эталона
  (см. ADR-0010); изменение контракта `Report` — ломает e2e и фронт,
  поэтому поля добавляются только опциональные.
